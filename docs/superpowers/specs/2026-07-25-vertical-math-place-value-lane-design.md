# 竖式数学“数位轨道”教学体验设计

**日期：** 2026-07-25
**状态：** 已确认设计
**范围：** `VerticalMathCard` 的逐步讲解、棋盘焦点、步骤导航和完成反馈；输入态只做必要文案修正

## 1. 设计定位

- **具体对象：** 小星老师在聊天中调用的竖式数学互动卡片。
- **主要受众：** 6–7 岁、可独立点击操作的儿童。
- **页面唯一任务：** 让孩子每一步都能立即看懂“现在算哪一位、怎么算、结果写哪里、是否进位或借位”。

本设计选择“数位轨道”方向：用一条贯穿竖式上下的高亮轨道连接当前参与计算的数字与结果落位；进位、借位、部分积和商位使用与其数学关系对应的辅助轨迹。它不是装饰，而是本步数据流的可视化。

## 2. 当前体验问题

### 2.1 教学焦点分散

- Header 显示一次步骤编号，Narrator 又显示一次，形成重复信息：`VerticalMathCard.ets:337-343`、`VerticalMathStepNarrator.ets:42-46`。
- 当前步骤主要依赖单个黄色格子表达，孩子仍需自己推断“参与计算的两个数字”和“结果写入位置”的关系：`VerticalMathBoardRow.ets:32-55`。
- 8/12vp 进度圆点更像状态装饰，不能表达下一步要做什么：`VerticalMathCard.ets:292-326`。

### 2.2 教学动作和按钮语义不一致

- 按钮始终显示“下一步”，没有说明下一步是“算个位”“算十位”还是“完成竖式”：`VerticalMathCard.ets:263-290`。
- 最后一个步骤一出现就自动调用 `onAnswer`，孩子看不到明确的确认动作：`VerticalMathCard.ets:157-174`。
- 初始态显示“第 0 / N 步”，不符合儿童心智模型。

### 2.3 进位与借位关系表达不足

- 加法求解器已在同一步生成本位结果和进位，数据顺序正确：`VerticalMathSolver.ets:203-246`；问题在于 UI 没有把两者呈现为同一个完整教学动作。
- 减法当前只为级联借位输出明显标记，直接借位被有意隐藏：`VerticalMathSolver.ets:398-470`。这与“每次按位计算都说明是否借位”的教学目标冲突。
- 持久化 top mark 能显示历史标记，但缺少本步从来源列到目标列的关系轨迹。

### 2.4 视觉语言仍有拼接感

紫色外壳、奶油棋盘、黄色格子、绿色完成态和珊瑚错误按钮分别有效，但缺少一个把它们组织成“数学教具”的核心结构。重置使用错误色，也会让非破坏性操作显得危险。

## 3. 目标与非目标

### 3.1 目标

1. 每个步骤只表达一个按位计算动作。
2. 本位结果与进位或借位信息必须在同一步出现。
3. 通过空间关系而非长文解释“数字从哪里来、写到哪里”。
4. 用动态按钮文案明确下一步动作。
5. 最终答案先展示，再由孩子确认回传。
6. 加、减、乘、除共享同一视觉语法，同时保留各自的课本结构。
7. 保持手机内联卡片与 `largeSize` 两种模式可用。

### 3.2 非目标

- 不改变四则运算的数值算法和求解顺序。
- 不改变 `vertical_math` 工具参数与结果 JSON。
- 不新增星星奖励类型。
- 不扩展运算范围；乘法仍要求第二个数为 `0–9`，除法仍要求除数为 `1–9`。
- 不重做 MessageBubble 或其他教学卡片。
- 不增加语音、震动或持续庆祝动画。

## 4. 视觉系统

### 4.1 六个语义色

| 令牌 | 浅色模式 | 深色模式 | 用途 |
|---|---|---|---|
| 云雾紫 | `#F2EEFB` | `#272238` | 卡片外壳与非焦点区域 |
| 练习册纸白 | `#FFFDF7` | `#302C27` | Narrator 与棋盘 |
| 铅笔墨色 | `#352E24` | `#F7F1E4` | 数字、横线和主要文字 |
| 当前位黄 | `#FFE15A` | `#E7C74E` | 当前轨道、当前结果、主按钮 |
| 完成薄荷绿 | `#56A779` | `#6FC294` | 已完成数位、最终确认 |
| 进位珊瑚红 | `#FF6B57` | `#FF7C6D` | 进位数字与移动轨迹 |

借位桥使用主题紫色的高对比变体，不新增第七个主色令牌。错误态继续使用项目通用错误资源色，不与教学状态混用。

### 4.2 字体

- 标题、讲解、按钮：HarmonyOS Sans。
- 数字棋盘：继续使用等宽字体，确保数位严格对齐。
- 当前算式使用 16–17vp Medium/Bold；棋盘数字在内联模式不小于 22vp，`largeSize` 不小于 26vp。
- 次要说明不小于 12vp；不再用 10–11vp 承担关键教学信息。

### 4.3 签名元素：数位轨道

当前数位不再只高亮三个独立格子，而是显示一条贯穿操作数、运算符横线和结果行的半透明黄色轨道。轨道编码以下关系：

```text
参与计算的上方数字
          │
参与计算的下方数字
          │
        横线
          │
      本位结果
```

轨道圆角 14vp、2px 描边，内部使用低透明度当前位黄。格子仍保留较强黄色填充，保证轨道和具体数字同时可读。

## 5. 页面层级

```text
┌─────────────────────────────────────┐
│ 竖式计算                       47＋28 │
├─────────────────────────────────────┤
│ [个位] 7＋8＝15                     │
│        个位写5，把1送到十位          │
├─────────────────────────────────────┤
│                                     │
│           十位   个位                │
│             4    [7]                 │
│        ＋   2    [8]                 │
│             ─────────                │
│                  [5]                 │
│          进位 1 → 十位               │
│                                     │
├─────────────────────────────────────┤
│ 个位完成                 下一步：十位 │
│ ━━━━━━━  ━━━━━━━━━  ━━━━━━━          │
├─────────────────────────────────────┤
│ [上一步]              [算十位]        │
│               重新开始               │
└─────────────────────────────────────┘
```

层级规则：

1. Header 只显示卡片名称和题目，不显示步骤编号。
2. Narrator 固定为“数位标签 + 当前算式 + 一个动作”。
3. 棋盘占据最大面积。
4. 底部进度使用分段条和动作文字，不再使用无语义圆点。
5. 仅保留一个强主按钮；“上一步”为次要按钮，“重新开始”为文字操作。

## 6. 交互状态

### 6.1 准备开始

- 不显示“第 0 步”。
- 提示：“从右边的个位开始算。”
- 主按钮读取第一步的 `actionLabel`，例如“开始算个位”。
- 棋盘只显示题目和横线，不显示结果。

### 6.2 当前位计算

以 `47 + 28` 的个位为例，同一步必须同时出现：

- 黄色个位轨道；
- `7`、`8` 和结果 `5` 的当前态高亮；
- 进位 `1`；
- “个位写 5，把 1 送到十位”的说明。

下一步按钮直接显示“算十位”，不增加独立“看看进位”步骤。

### 6.3 下一数位

- 轨道水平移动到下一列。
- 已完成列切换为薄荷绿。
- 上一步产生的进位标记保留，并纳入当前列的视觉范围。
- 文案说明进位是否参与，以及本步是否产生新的进位。

### 6.4 完成与回传

- 求解器最后一步只展示完整答案，不立即回传。
- 主按钮变为“完成，告诉小星老师”。
- 点击后调用一次 `onAnswer`，按钮进入已完成态并禁用重复提交。
- `isAnswered` 时间线回放默认显示最终答案；提供“重新演示”从准备态开始，但不会再次回传。

## 7. 四则运算规则

### 7.1 加法

- 黄色轨道覆盖当前列。
- 本位结果与 `carryOut` 在同一步出现。
- 珊瑚色进位数字显示在目标列上方，并用短虚线指向目标列。
- 无进位时显示简短“没有新进位”，不渲染空标记。

验收例：`47 + 28`。

### 7.2 减法

- 黄色轨道覆盖当前列。
- 直接借位和级联借位都必须显示。
- 紫色借位桥连接提供数字的高位与当前目标位。
- 本位结果、借位来源和被修改的高位在同一步出现。
- 借位讲解必须以当前被减数位为主语，例如“3 不够减 8，从十位借 1”；不得沿用当前实现中 `${dB} 不够减` 的错误主语。
- 历史借位标记可保留，但只有本步借位桥使用强强调。

验收例：直接借位题与 `503 - 278`。

### 7.3 乘法

当前实现约束为“多位被乘数 × 一位乘数”，验收例使用 `988 × 6`。

- 当前被乘数位保持黄色焦点。
- 当前乘数 `6` 同时高亮。
- 当前部分积整行使用黄色“落位带”，展示它占据的数位范围。
- 已完成部分积转为薄荷绿。
- 不强行使用单列轨道，以免破坏课本错位结构。

### 7.4 除法

- 保持现有一位数除数约束。
- 轨道连接当前被除数片段与商的落位。
- “不够除”步骤只高亮当前片段，不渲染无意义商位。
- 每次试商同步展示商、乘积与余数；下一步随落位向右移动。

验收例：`84 ÷ 4`、有余数题和首位不够除题。

## 8. 数据与组件设计

### 8.1 求解器模型

保留 `VerticalMathHighlight` 作为格子状态的唯一数据源；新增只描述跨格关系的覆盖层模型，避免 UI 解析 narration 文本，也避免与现有 highlight 重复：

```ts
export type VerticalMathOverlayKind =
  'carry_path' | 'borrow_bridge' | 'partial_band' | 'division_lane'

export class VerticalMathOverlay {
  kind: VerticalMathOverlayKind = 'carry_path'
  sourceColumn: number = -1
  targetColumn: number = -1
  rowIndex: number = -1
  startColumn: number = -1
  endColumn: number = -1
  value: string = ''
}

export class VerticalMathStep {
  title: string = ''
  narration: string = ''
  placeLabel: string = ''
  actionLabel: string = ''
  rows: VerticalMathBoardRow[] = []
  highlights: VerticalMathHighlight[] = []
  overlays: VerticalMathOverlay[] = []
  showFinalLine?: boolean
  showResultRow?: boolean
}
```

职责：

- `highlights`：单格 active/done/carry/borrow/quotient 状态。
- `overlays`：跨列轨道、借位桥、部分积落位带和除法连接。
- `placeLabel`：Narrator 的短标签，如“个位”“十位”“完成”。
- `actionLabel`：进入该步骤前的按钮文案，如“算个位”“完成竖式”。

### 8.2 `VerticalMathCard.ets`

- 删除 Header 中的步骤数字。
- 将 `StepProgressDots` 替换为分段进度条。
- 主按钮读取下一步的 `actionLabel`。
- `handleNext` 只推进步骤；当最终答案已展示时，下一次点击才提交。
- `aboutToAppear` 在 `isAnswered === true` 时同步设置 `hasAnswered = true`，确保历史回放永远不会重新提交。
- `hasAnswered` 继续作为防重复提交守卫。
- 回放态的“重新演示”只改变 `visibleStepCount`，不清除 `hasAnswered`。

### 8.3 `VerticalMathStepNarrator.ets`

- 删除重复的 `operationLabel`。
- 渲染 `placeLabel`、当前算式和动作句。
- 讲解最多两行；不通过截断隐藏数学信息。
- 保留单次过渡动画，但不使用横向大幅位移。

### 8.4 `VerticalMathBoard.ets`

拆成三个清晰职责的 Builder：

1. `BoardRows`：继续渲染原有行与格子。
2. `PlaceValueLaneOverlay`：根据当前 active highlights 绘制当前列轨道。
3. `StepRelationOverlays`：根据 `overlays` 绘制进位、借位桥、部分积带或除法轨道。

不把数学计算放进组件；组件只做坐标换算和样式渲染。

### 8.5 `VerticalMathBoardRow.ets`

- 保持等宽列和 highlight 颜色映射。
- 当前格增加轻微底部阴影，与贯穿轨道区分层级。
- 关键数字触控不可操作，因此不增加伪按钮样式。

### 8.6 `VerticalMathColors.ets`

将固定颜色收敛为第 4 节的语义令牌。文件新增 `VerticalMathPalette` 命名接口和 `resolveVerticalMathPalette(isDarkMode)` 纯函数；`VerticalMathCard` 读取 `AppUiState.isDarkMode`，把布尔值传给 Narrator、Board 和 BoardRow，由子组件通过同一 resolver 取得颜色。这样浅色/深色切换只有一个来源，不在各 Builder 内散落条件分支。错误色继续读取项目资源，不复用进位珊瑚色。

## 9. 动效与可访问性

### 9.1 动效

- 轨道切换：180ms EaseInOut，水平移动。
- 进位移动：220ms，一次短路径移动到目标列。
- 当前结果出现：180ms opacity + 0.96→1 scale。
- 完成确认：260ms，从当前位黄过渡为完成薄荷绿。
- 不使用循环动画、彩带或持续弹跳。
- 系统启用减少动态效果时，直接切换最终状态。

### 9.2 可访问性

- 所有按钮高度至少 48vp。
- 颜色之外同时使用轨道、文字标签和位置表达状态。
- 操作按钮增加明确 accessibilityLabel。
- Narrator 变化时提供可朗读的完整步骤文本。
- 禁用态仍保持足够文字对比度。

## 10. 错误与边界文案

输入态只做必要修正：

| 当前表达 | 新表达 |
|---|---|
| `A` / `B` | 输入框上方显示 `第一个数` / `第二个数`，框内只放数字示例 |
| `请输入 0–999 之间的整数` | `请输入 0 到 999 的数字` |
| `乘法的第二个数请输入 0–9` | `第二个数只能填一位数字` |
| `除数请输入 1–9` | `除数请填 1 到 9` |
| `除数不能为 0` | `0 不能做除数，换一个数字吧` |

减法 `A < B` 继续提示“不够减，建议换一道题哦”。错误出现后保留输入值和运算类型，孩子可以直接修正。

## 11. 测试与验收

### 11.1 求解器单元测试

补充或更新 Hypium 测试：

1. `47 + 28` 的个位步骤同时包含结果 `5`、进位 `1` 和 `carry_path`。
2. 无进位加法不产生空 `carry_path`。
3. 直接借位产生 `borrow_bridge`。
4. `503 - 278` 的级联借位包含正确来源列、目标列和持久标记。
5. `988 × 6` 每个步骤的 `partial_band` 范围与部分积非空格范围一致。
6. `84 ÷ 4` 的 `division_lane` 连接当前片段和商位。
7. 首位不够除时不产生 quotient 目标。
8. 每个非最终步骤都有非空 `placeLabel` 和 `actionLabel`。

### 11.2 组件人工验收

- 初始态不出现“第 0 步”。
- Header、Narrator 和进度区不重复显示同一编号。
- 结果与进位/借位在同一步出现。
- 主按钮文案随下一教学动作变化。
- 最终答案出现时尚未回传；点击确认后只回传一次。
- 回放态可以重新演示且不重复回传。
- 内联与 `largeSize` 模式均无裁切。
- 浅色、深色和减少动态效果模式可读。

### 11.3 工程验证

- DevEco Studio 运行 `VerticalMathSolver.test.ets`。
- clean `assembleHap` 验证 ArkTS 严格类型与 Builder 约束。
- 在真机聊天中手测加、减、乘、除及已回答回放。
