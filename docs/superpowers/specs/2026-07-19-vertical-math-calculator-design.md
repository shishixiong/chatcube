# 儿童竖式数学计算器设计

**日期：** 2026-07-19
**状态：** 已确认设计，待实施
**范围：** Cube Chat 内的小星老师竖式数学互动卡片；Web 视觉原型仅用于设计确认，不作为正式交付物

## 1. 目标与范围

新增一个适合 6–12 岁儿童的 `vertical_math` 互动工具，在聊天中展示加、减、乘、除的标准小学竖式，并通过“下一步”逐步揭示计算过程。

本期目标：

- 输入 A、B（整数，范围 0–999）并选择加、减、乘、除。
- 通过“开始计算”生成题目，但初始只展示题目、运算符和横线，不展示计算步骤。
- 每次点击“下一步”只新增一个步骤；“上一步”可以回退。
- 在竖式旁边同步显示自然语言中文讲解。
- 加减法显示数位对齐、进位、退位圆点、划线和新数字。
- 乘法显示按位对齐的多行部分积。
- 除法显示除数为一位数的标准长除法：看首位、试商、乘减、落位。
- 适配探险游戏风格和手机窄屏布局。

非目标：

- 本期不新增星星奖励活动类型，避免扩散 `StarEventModels.ets` 的联合类型改动；完成状态只回传工具结果。
- Web 原型不进入正式产品代码，不新增 Web 运行时或独立 Web 构建链路。
- 不在卡片内实现自由编辑每个中间数字；所有计算过程由纯逻辑层生成。

## 2. 已确认的产品决策

### 2.1 交付方式

- Web 版本：仅作为浏览器视觉原型，用于确认布局和视觉方向。
- 正式版本：HarmonyOS 原生 ArkTS 聊天互动卡片。
- 入口：由小星老师通过聊天工具调用打开，不新增独立导航页面。
- 技术基础：复用现有教学工具调用链和卡片组件模式。

当前仓库历史中存在早期 `feat(vertical-math)` 实现痕迹。实施时可以参考其拆分思路，但必须按当前分支的架构、严格 ArkTS 规则和本设计重新审查，不直接盲目合并。

### 2.2 运算约束

- A、B 都是整数，范围 `0–999`。
- 输入框使用数字键盘并过滤非数字字符，最多保留 3 位。
- 减法要求 `A >= B`，否则提示“不够减，建议换一道题哦”。
- 乘法要求 B 为一位数 `0–9`，符合“多位数 × 一位数”。
- 除法要求 B 为一位数 `1–9`，不允许除数为 0。
- 除法同时支持整除和有余数。

## 3. 整体架构

```text
AI 调用 vertical_math
        ↓
ToolExecutionService
        ↓
等待孩子操作的 VerticalMathCard
   ├── VerticalMathSolver
   ├── VerticalMathBoard
   └── VerticalMathStepNarrator
        ↓
孩子点击下一步 / 上一步
        ↓
完成后 onAnswer 回传结果
```

### 3.1 文件职责

- `entry/src/main/ets/utils/VerticalMathSolver.ets`
  - 输入校验、四则运算、步骤计划和竖式行数据。
  - 不依赖 ArkUI，优先覆盖纯函数单元测试。
- `entry/src/main/ets/utils/VerticalMathColors.ets`
  - 探险主题的黑板、背景、高亮、完成态、错误态等颜色常量。
- `entry/src/main/ets/components/verticalMath/VerticalMathBoard.ets`
  - 左侧竖式区域，负责等宽数位格、横线、标记和逐步可见内容。
- `entry/src/main/ets/components/verticalMath/VerticalMathStepNarrator.ets`
  - 右侧步骤解说列表，负责当前步骤、已完成步骤和自动滚动。
- `entry/src/main/ets/components/VerticalMathCard.ets`
  - 输入区、运算符选择、控制按钮、主题外壳和本地交互状态。
  - 通过 `onAnswer` 接入现有 pending tool answer 机制。
- `entry/src/main/ets/config/BuiltinTools.ets`
  - 注册 `vertical_math` 的 schema 和工具配置。
- `entry/src/main/ets/services/ToolExecutionService.ets`
  - 分发工具并等待卡片完成结果。
- `entry/src/main/ets/components/MessageBubble.ets`
  - 在聊天消息中挂载 `VerticalMathCard`。

`VerticalMathCard` 只负责状态和事件，所有计算结果、中间行和自然语言步骤均由 `VerticalMathSolver` 生成，避免 UI 层重复计算。

## 4. 状态与数据模型

### 4.1 卡片状态

```text
idle        → 输入区可编辑，竖式区域为空
calculating → 已生成题目，步骤尚未揭示
playing     → 正在逐步播放
completed   → 全部步骤完成，结果已回传
error       → 输入或运算约束不满足
```

核心本地状态：

- `operandA: string`
- `operandB: string`
- `selectedOperation: VerticalMathOperation`
- `solution: VerticalMathSolution | null`
- `visibleStepCount: number`，初始为 0
- `isComplete: boolean`
- `errorMessage: string`

点击“开始计算”后生成 `solution` 并将 `visibleStepCount` 重置为 0。因此此时只显示题目和横线；第一次点击“下一步”才显示第一个“数位对齐”步骤。

### 4.2 纯逻辑模型

```text
VerticalMathSolution
├── operation
├── operandA
├── operandB
├── result
├── remainder
├── displayRows
└── steps[]

VerticalMathStep
├── title
├── narration
├── highlightedPositions
├── completedPositions
├── carryMarks
├── borrowMarks
├── intermediateRows
└── isFinal
```

`VerticalMathBoard` 根据 `displayRows` 和前 `visibleStepCount` 个步骤渲染，不在 Builder 内调用计算函数。`VerticalMathStepNarrator` 使用同一批步骤数据，确保文字和竖式始终同步。

## 5. 四则运算的教学步骤

### 5.1 加法

以 `47 + 28` 为例：

1. 数位对齐：个位对个位，十位对十位。
2. 个位：`7 + 8 = 15`，写 5，红色小 1 进到十位。
3. 十位：`4 + 2 + 1 = 7`。
4. 从右到左完成并显示答案 `75`。

进位数字放在对应目标位的正上方，使用红色小字号；当前正在计算的列使用荧光黄背景。

### 5.2 减法

以需要退位的题目为测试重点：

1. 数位对齐。
2. 当前位够减时直接计算。
3. 当前位不够减时，在被减数上方显示小圆点 `•`，划掉原数字并写出退位后的新数字。
4. 继续计算当前位和后续位。
5. 显示最终结果。

A 小于 B 时不生成负数竖式，直接显示错误提示。

### 5.3 乘法

严格采用小学教材的“分层部分积”格式，不将所有中间结果合并为一行。

以 `988 × 6` 为例，数位格为“千、百、十、个”：

```text
       9  8  8
   ×         6
   ────────────
             4  8       ← 个位 8×6=48，占十位、个位
          4  8          ← 十位 8×6=48，整体左移一格
   ＋   5  4            ← 百位 9×6=54，整体左移两格
   ────────────
       5  9  2  8
```

具体渲染规则：

- 每个部分积绑定到明确的位值格，禁止统一右对齐。
- 个位部分积 `48` 放在十位和个位。
- 十位部分积 `48` 向左移动一格，放在百位和十位。
- 百位部分积 `54` 向左移动两格，放在千位和百位。
- 空出的位值格保留为空，不删除列结构。
- 最后一行部分积前显示 `＋`。
- 所有部分积完成后再显示第二条横线和最终答案 `5928`。
- 当前被乘数字位和对应部分积使用荧光黄/绿色状态切换。
- 步骤说明示例：
  - “个位：8×6=48，部分积放在十位和个位。”
  - “十位：8×6=48，部分积向左移动一格。”
  - “百位：9×6=54，部分积向左移动两格。”
  - “按位相加，得到 5928。”

这种图片式乘法不显示额外进位标记；每一行的十位数字已经包含在部分积中，只通过部分积的位值对齐和按位相加完成教学。

### 5.4 除法

除数限制为一位数，使用厂字形长除号。步骤顺序固定：

1. 看首位：判断当前被除数片段是否够除。
2. 试商：在商的位置写出商数字。
3. 乘：除数乘商，写在当前片段下方。
4. 减：用当前片段减去乘积。
5. 落位：把下一位数字拉到余数右侧。
6. 重复以上步骤，直到被除数用完。
7. 显示商；若余数不为 0，显示“商 X，余数 Y”。

`0 ÷ B` 显示商 0；当首位小于除数时，步骤说明“首位不够除，先看下一位”，不渲染无意义的前导 0。

## 6. 视觉与布局

### 6.1 探险游戏风格

- 背景：淡紫蓝渐变，避免纯白。
- 主黑板：深紫渐变、圆角、柔和阴影。
- 标题：`🧮 小小数学家 · 竖式闯关`。
- 状态信息：显示“第 X/Y 步”，完成后显示星星和“闯关完成”。
- 当前位：荧光黄背景和轻微放大。
- 已完成位/部分积：薄荷绿色和绿色勾选。
- 错误：珊瑚红提示卡。
- 字体：大号、等宽、圆润；数字格保持等宽，保证位值列对齐。

### 6.2 布局

```text
┌─────────────────────────────────────┐
│ 🧮 小小数学家 · 竖式闯关   第 2/6 步 │
├─────────────────────────────────────┤
│ [数字A] [＋] [数字B] [开始计算]       │
│ [＋] [－] [×] [÷]                    │
├─────────────────────────────────────┤
│ [上一步]       [下一步]       [重置]  │
├───────────────────┬─────────────────┤
│                   │                 │
│   探险黑板 70%     │  步骤解说 30%    │
│                   │                 │
└───────────────────┴─────────────────┘
```

- 平板/横屏：黑板占 70%，解说列表占 30%。
- 手机窄屏：黑板在上，解说列表在下。
- 步骤列表自动滚动到最新步骤。
- 主要按钮触控区域不小于 44vp。

### 6.3 动画

- 新步骤淡入并轻微向上移动。
- 当前位荧光黄渐入。
- 加法进位或减法退位标记从上方落入；乘法部分积不使用额外进位标记。
- 乘法部分积按位值格滑入。
- 完成星星短暂缩放，不阻塞后续操作。

## 7. 工具契约与结果回传

工具名：`vertical_math`。

参数允许 AI 预填，也允许孩子在卡片内重新选择：

```json
{
  "operation": "add | subtract | multiply | divide",
  "operand_a": 0,
  "operand_b": 0
}
```

三个字段可以为空。为空时显示完整输入区；有值时预填但仍允许修改。

只有全部步骤完成后才调用 `onAnswer`，示例结果：

```json
{
  "completed": true,
  "operation": "multiply",
  "operand_a": 988,
  "operand_b": 6,
  "result": 5928,
  "remainder": 0,
  "step_count": 5
}
```

每一步不单独发送给 AI，避免对话被过程数据打断。非法输入不触发 `onAnswer`。

## 8. 错误处理

- 空输入：`请先输入两个数字`。
- 非数字字符：输入时过滤。
- 超出 `0–999`：限制到 3 位。
- 减法 A 小于 B：`不够减，建议换一道题哦`。
- 乘法 B 不在 `0–9`：`乘法的第二个数请输入 0–9`。
- 除法 B 不在 `1–9`：`除数请输入 1–9`。
- 除数为 0：开始计算前拦截。
- 除法有余数：结果显示商和余数。

## 9. 测试与验收

优先为 `VerticalMathSolver.ets` 补纯函数测试：

1. `47 + 28`：个位进位、十位加进位。
2. `503 - 278`：连续退位、圆点、划线和新数字。
3. `988 × 6`：`48 / 48 / 54` 三行部分积的位值对齐和 `5928`。
4. `84 ÷ 4`：整除长除法。
5. `85 ÷ 4`：商和余数。
6. `3 ÷ 7`：首位不够除。
7. `0`、`999`、空输入和非法字符边界。
8. 减法负数、乘法多位除数、除数为 0 等限制。

组件层人工验收：

- 开始计算后初始不显示步骤。
- 第一次下一步显示“数位对齐”。
- 上一步/下一步状态完全可逆。
- 四种运算的高亮、勾选、进位、退位和横线同步。
- 乘法十位、百位部分积按位值格向左错位。
- 除法厂字形结构和落位过程清晰。
- 步骤列表自动跟随最新步骤。
- 手机窄屏自动改为上下布局。
- 完成后只回传一次结果。

HarmonyOS 验证使用项目现有约定：优先运行 `assembleHap` 做 ArkTS 严格编译验证；纯逻辑测试在 DevEco Studio 的 Hypium 测试环境中执行。
