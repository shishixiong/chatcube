# 3D 小词屋「走进去」第一人称设计

日期：2026-11-06
组件：`entry/src/main/ets/components/room/RoomEnglishCard.ets` + `entry/src/main/resources/rawfile/room3d/`

## 背景

小词屋原来的交互是「上帝视角」：整间房悬在画面中央，拖动旋转、双指缩放，点家具看单词。
这套视角看得全，但孩子始终在**房间外面**看，和「走进一个家、指着东西说出名字」的真实语境差一层。
这次加一个可选的第一人称视角，让单间房可以「走进去」：站着、转身、往前走两步，走到冰箱前再点它。

全屋视图不放第一人称：四间房之间的地面没有建模，站进去只会看到模型外侧的空白。

## 形态

| | 上帝视角（默认） | 走进去 |
| --- | --- | --- |
| 入口 | 页面默认 | 顶部卡片「走进去」 |
| 可用范围 | 全屋 + 四间房 | 只有四间房（`overview` 强制拒绝） |
| 相机 | 轨道相机（`orbit.*`） | `WalkCamera`（视线高度 1.25m，俯仰 ±69°） |
| 返回 | — | 顶部卡片变「全景」；切到全屋、开始带逛/答题也会自动回轨道 |

- 一个渲染循环、一台透视相机。`RoomExperience.animate()` 按 `mode` 分支，走路时交给 `animateWalk(dt)`。
- 拾取仍然走 `pickAt → onTap → chooseObject`：单词卡、发音、进度、带逛、出题全部不变。
- 走路时轻点 = 原来的点击；拖动超过 7px 才算环顾，所以「点冰箱」不会被误判成转头。

## 相机与碰撞

`rawfile/room3d/assets/walk-camera.js`，只做相机，不碰业务。

- 坐标系就是户型坐标（米），地面 y = 0.03；`yaw 0 = 朝 +z`，与轨道相机角度约定一致。
- 出生点写在 `room-layout.js` 的 `spawns`，四间房各一个（世界坐标 + 朝向）。
- 墙体：`WALK_INSET` 按房间短边自适应内收（0.22–0.42m），避免贴脸穿墙。
- 家具：复用 `roomHitboxes.overview`——家具、隔墙、门框的盒子。取世界 AABB 后按最近边软推挤，
  分轴推进，所以能贴着家具侧面滑过去。身体半径 `RADIUS = 0.26m`。
- 两类盒子不挡人：
  - 底边高于 1.2m 的挂件（画、钟、空调），挡不到膝盖；
  - 顶面低于 0.18m 的贴地物（地毯、地垫、门槛石），本来就是踩上去的。
- 出生点被家具占住时（户型数据改动），先软推挤，还站不住就在房间 0.2m 网格里找最近的空地。
- 阴影相机跟着脚底走（单间房半径 6m），走到房间另一头不会掉进阴影外。
- 走路时不藏墙：相机在屋里，藏掉北墙/西墙会看到模型外侧的空洞。

## 标签分档

走路时标签是「发现」的主要反馈，但不能一眼糊满屏。

- `getLabelAnchors()` 多返回水平距离 `distance`、与眼睛的高差 `lift`、世界坐标 `world`。
- `labelTier(distance, 看见多远)`：
  - `near`（≤ 0.62 × 看见多远）：全彩；
  - `middle`：半透明（还没走到跟前）；
  - `hidden`：超出「看见多远」，先藏起来。
- 摆放顺序按距离近的先摆；挤不下时远景标签收起，近景和选中的一定留下。
- 安全区躲开顶部卡片（96/104px）和底部控件（150/120px，竖屏更高）。

## 方位提示

站定（脚步和转头都停 0.45 秒）后报一句最近的东西：「垃圾桶，身后，在 1.4 米外」。

- 方位用世界坐标算：`bearing()` 给偏角，`direction()` 分 6 档（正前方 / 左前方 / 右前方 / 左手边 / 右手边 / 身后）。
  用屏幕投影算会被透视骗——身后的东西会翻到画面另一侧。
- 距离三档：1.2m 内「就在手边」、4.2m 内「在 N 米外」、再远「在房间另一头」；
  和视线差 1m 以上才补「要抬头看 / 要低头找」。
- 触发节流：
  - 同一样东西 9 秒内不重复；
  - 第二次点同一件物品才补方位——第一次已经念中文 + 英文，再叠一句要 8 秒开外，孩子听不完；
  - 方位开关默认开，记在 `localStorage: wordroom.walkHint`。
- 语音走原生桥：`bridgeCall('speak', text, '')`，由 `RoomEnglishCard.speakWord` 交给系统 TTS（zh-CN）。

## 手势与键盘

| 操作 | 行为 |
| --- | --- |
| 单指拖动 | 环顾（±69° 俯仰限制） |
| 双指张合 | 调节「看见多远」（1.5–8m） |
| 滚轮 | 同上 |
| 按住向上箭头 | 前进；松手停 |
| WASD / 方向键 | 走路 / 转头（`document` 级监听，画布失焦也能走） |
| 点物品 | 打开单词卡（不变） |

- 键盘监听挂在 `document` 上，但焦点在输入控件里时不抢键（滑块调值、输入框打字）。
- 词汇表弹层打开时 `setInputBlocked(true)`：停掉键盘走路并清空按键状态，关掉弹层不会自己动。
- 窗口失焦 / 切到后台会松开「按住前进」，不会一直走。

## 原生集成

- `RoomNativeBridge.onMode(mode)`：Web 每次视角变化（按钮、换房间、全屋强制回轨道、开始带逛）都通知原生。
- 原生 `@Local walkMode` 只用来改标题栏提示语（「第一人称 · 拖动环顾，按住向上箭头前进」）。
- **切换入口只有 Web 顶部那张卡**：原生不再叠一个浮层按钮。浮层会盖住 Web 的标题卡（两者都在左上角），
  而且两个按钮表示同一个状态，孩子会以为有两个不同的东西。
- 开始带逛 / 找一找时自动退出第一人称：课程镜头要自己控制机位。

## 验证

Web 侧原来没有测试基建，这次补了两层，都不进 HAP：

- `scripts/verify-room3d-data.mjs`（无依赖）：DOM id / 脚本顺序 / 桥接方法 /
  `WordRoomApp` API / CSS 规则 / 方位档位 / 出生点数据；
- `scripts/room3d-walk-test/`（`npm install` 只装 jsdom）：用 jsdom 打开真实
  `index.html` + 仓库自带 `three.min.js`，只把 `WebGLRenderer` 换成桩，
  几何、射线拾取、碰撞盒、标签分档、方位播报全是真的。

集成测试 31 项，覆盖：

- 全屋拒绝第一人称；单间房进入后按钮/控件/重置视角状态正确，「走进去 / 回到全景」文案跟着翻；
- 拖动环顾会让方位发生变化；按住前进 1 秒走约 0.9m，松手不漂；W/S/A 三个方向都能走，斜着走不会更快；
- 撞墙停在房间内，不穿进家具（83 个碰撞盒，地毯已按可跨越处理）；
- 四间房出生点都在可行走区域、不压家具；蹲下 0.80m、站起 1.25m；
- 「看见多远」1.5m 时 0 个标签、8m 时 3 个；滚轮 5.0 → 5.4m；
- 站定后播报方位、关掉开关后不播报；再点同一件物品，3.2 秒后补一句方位；
- 走路时点物品仍打开单词卡；换房间落在新房间；回全屋自动回轨道；原生 `setMode` 的请求会等到选房间再兑现；
- 方位几何 13 个角度落在预期档位；措辞三档 + 抬头/低头；
- 词汇表打开时 WASD 不移动；按住 W 时切后台/切视角，回来不会自己走；开始带逛自动退出第一人称。

未在真机/DevEco 上跑过：ArkTS 改动只做了静态审查（ArkWeb 代理方法、`@Local` 状态、标题栏文案）。

## 已知边界

- 全屋视图不能走（没有房间之间的地面）。
- 房间之间不能走通：换房间是「传送」到新房间的出生点。
- 走在房间边缘时偶尔会被家具盒推开一点，属于软推挤的正常表现。
- 任务是「点选找物」，还没做「走过去找到 xx」的走路任务。
