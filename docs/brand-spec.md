**来源**：chatcube 项目 `entry/src/main/ets/components/kids/KidsBrandTokens.ets`（应用内真实令牌，非生成值）

## 字体

- 展示（标题 / 数字）：`'Yuanti SC', 'Hiragino Maru Gothic ProN', 'PingFang SC', 'Hiragino Sans GB', system-ui, sans-serif` — 圆润、亲和，适合低龄。
- 正文：`'PingFang SC', 'Hiragino Sans GB', system-ui, -apple-system, sans-serif`。
- 等宽（时间 / 计数 / 眉标）：`ui-monospace, 'SF Mono', Menlo, monospace`。

## 观察到的视觉规则

1. **暖米白底 + 暖黑字**，从不使用纯白 / 纯黑；卡片是 `--surface` 上的 1px `--border` 描边，配极轻暖色投影。
2. **大圆角 + 大触控目标**：卡片 18–24px 圆角，可点目标 ≥ 44px，儿童可读字号偏大。
3. **唯一暖橙强调色**出现在主 CTA 与主卡渐变上，每屏至多两处；学科色只用于图标块淡底与图标，不作大面积铺色。
4. **不使用紫/渐变大背景**：主卡是暖橙渐变，其余层为纯色。
5. **星星是核心奖励符号**：金色 `--star`，搭配深棕文字，出现在 hero 徽章、会话卡、明细面板。

# 第二部分 · 审美契约（v2 · 已冻结 2026-09-14）

> 这一部分回答「什么是好看的设计」。色彩/字体令牌已由第一部分锁定；本部分是结构、密度、动效、素材与验收标尺。**已于本轮冻结**，后续迭代默认遵守；如需变更须显式提出并更新本文。

## 0. 冻结决策记录（2026-09-14）

本轮 direction 表单的四项决定，作为上述规则的优先解释：

| 决策项 | 冻结选项 | 生效含义 |
|---|---|---|
| 首页信息优先级 | 保持三段式 | 保留「问候 + 继续学习 + 学科区」三段结构；首屏焦点唯一为「继续学习」hero，问候行降为轻量信息条，学科区紧随其后作为下一步，不与 hero 争夺焦点。 |
| 素材与插画标准 | 纯 UI + 内联 SVG | 全站无照片、无生成插画、无外链；图标一律内联 monoline SVG，"图像感"由令牌色几何块 + 文字承担。§9 的摄影/生成插画分支本轮不启用。 |
| 动效基调 | 克制 | 只保留面板滑入、按压反馈、toast、答对数值过渡；无循环、无自动轮播、无持续运动。时长与曲线见 §8。 |
| 交付范围 | 先冻结规范，再改首页 | 本轮先冻结本文，再据此修改 `kids-learning-home.html`；本文是后续所有改动的验收基准。 |

## 1. 受众

- **主用户：5–7 岁低龄儿童**（源自 `2026-09-10-kids-mode-design.md`「目标用户 5 岁左右」）。识字量有限，靠图形与色彩理解；注意力单次 3–8 分钟；精细动作未成熟。
- **次用户：家长**（决策者）。关心安全、可见的进度、可控性；家长门之后才进入成人系统。

## 2. 业务目标（按优先级）

1. **零迷路**：任何路径一步之内进入学习，孩子不需要读说明。
2. **养成每日回访**：当天星星 + 按天记录制造「今天还没来」的动机。
3. **四个明确入口**：学数学 / 学英语 / 学语文 / 小游戏，各是一个专用 agent，而不是工具杂货铺。
4. **家长 10 秒读懂**：一眼看清孩子今天学了什么、得了多少星。

## 3. 品牌气质

- **有温度的耐心**：像一位坐在旁边陪写作业的老师，不是一台游戏机。
- 关键词：绘本感 / 圆润 / 明亮不刺眼 / 有回应 / 不喧哗。
- 反面：幼稚化（卡通乐园）、竞赛化（排名、倒计时压迫）、冷科技感。

## 4. 风格参考锚点（方法论参考，不复制任何具体品牌）

- 圆润与「纸质感」：暖米白纸面 + 圆体 + 大圆角，是低龄绘本 App 的公共语言。
- 信息克制：一屏一个焦点，蒙特梭利式留白。
- 反馈即时：答对立刻给星星与肯定语；不惩罚、不倒扣。

## 5. 信息密度规则

- **三段式、单一焦点**：问候行（信息，非焦点）→「继续学习」hero（唯一焦点）→ 学科区（下一步，首屏可见其学科卡）。首屏可点区域为：继续学习主 CTA、看明细、学科卡；顶部星星为状态展示。首屏不出现第三层信息。
- **学科卡 2×2**：每卡 = 图标 + 名称 + 一句副标题 + 一行状态。不加进度条、时长、难度标签。
- **学习乐园按天分组**：每天一行摘要 + 记录列表；同日超过 3 条折叠为「共 N 次」。
- 总则：一屏若需滚动两次才看到下一块，砍内容，不缩字号。

## 6. 色彩标准

- 只用第一部分锁定令牌，不引入新色。
- 唯一暖橙 `--accent` 每屏 ≤ 2 处（眉标 + 主 CTA）。
- 四个学科色只用于图标底色（15% 混合，用 `--x`）与图标/文字（用 `--x-ink`；原色作文字不达标），不作大面积铺色，不与暖橙争夺注意力。
- 星星金是奖励语义，只出现在星星相关处。
- 状态语义借用学科色：答对 = 英语绿，答错 = 语文橙红（不新增状态色）。

## 7. 字体标准

- 展示圆体 `--font-display`，正文系统黑体 `--font-body`，数字 `--font-mono`。
- 儿童可读下限：正文 ≥ 16px，卡片标题 17–19px，hero 标题 23px；不出现 < 12px 的正文。
- 所有数字用 `.num`（等宽、tabular）。

## 8. 动效标准

- **目的**：确认操作、引导注意力；不做装饰。
- 时长/曲线：面板 300–320ms `cubic-bezier(.22,.61,.36,1)`；按压 60ms；toast 1900ms。
- 必须有：`:focus-visible` 聚焦环、按压下沉 1px、面板滑入、星星数值变化有过渡。
- 禁止：循环动画、自动轮播、视差、>400ms 转场、任何持续运动。
- 尊重 `prefers-reduced-motion`。

## 9. 素材标准

- **本轮锁定 `ui_only`**：无照片、无生成插画、无外链；以令牌色几何块 + 内联 monoline SVG 图标 + 文字表达。任何新增图像仍须内联为 data URI 才允许出现。
- **若未来解锁角色/插画**（需显式提出）：优先真实摄影（学习场景、文具）；生成插画仅在用户明确同意后使用，且全站统一风格（绘本扁涂，无描边渐变，无 emoji）。
- **禁止**：emoji 当图标、网络热链、未替换的灰色占位块。

## 10. 反模式清单（不能出现的 AI 味 / 模板感）

1. 紫色或多色渐变铺底；暖橙之外的第二强调色系统。
2. emoji 充当功能图标或头像。
3. 每个标题旁都配图标；每张卡都配「了解更多」。
4. 空洞指标与占位文案（如「10× 提升」「Feature One」）。
5. 为演示者而存在的控制面板（无产品意义的开关/参数）。
6. 对称到底的等大卡片墙（字数一致、无重点层级）。
7. 冷科技感（纯黑/纯白、细字距标题）。
8. 过度幼稚化（糖果色、拟声词堆砌、闪烁）。

## 11. 验收标尺（3 轴，各 0–10，ship 阈值 ≥ 8）

- **清晰度**：5 岁孩子能否在 3 秒内说出「点哪里开始」。
- **温度**：是否像一位鼓励他的老师，而非一台机器。
- **克制**：是否存在任何一处装饰，删掉之后更好。

## 12. 收尾决策（v2.1 · 2026-09-14）

上一轮遗留的三项待确认，已按推荐默认落地，作为后续迭代的既有约束：

1. **真实 TTS 发音 · 已启用**：英语「听音选词」的喇叭改为调用设备原生语音引擎（`speechSynthesis`）实时朗读单词，`rate 0.82` / `pitch 1.05`、优先匹配 `en-US` 音色。这是浏览器/系统能力，不引入音频文件、不外链，符合 §9 的 `ui_only`。环境不支持时降级为文字提示，不静默失败。语文拼音题**不**加朗读——会直接泄露答案。
2. **覆盖范围 · 首页 + 家长入口**：本轮把冻结规范推到家长入口。`家长入口` 不再是占位 toast，而是「算术验证门 → 家长今日概览」，落实 §2 业务目标 4「家长 10 秒读懂」。学习乐园**不另设详情页**：现有的按天分组列表（每天摘要 + 记录列表 + 当日星星）已完整表达每日记录，再设一页属冗余，违反 §11「克制」。未来如需历史趋势，明确交给家长端。
3. **无障碍 MCP · 本轮不可用，改本地核验**：运行时的 MCP 为 `0 enabled / 39 templates`，模板可见但不可调用。无障碍不降级：改用本地脚本核验（对比度 28/28、触控目标 ≥44px、`:focus-visible` 聚焦环、`prefers-reduced-motion`），结果见第一部分「无障碍修正」。家长验证门的选项按钮同样沿用 `.qopt` 的 46px 触控高度与聚焦环。

## 13. 交付打磨（v2.2 · 2026-09-14）

按 `impeccable-design-polish` 对 `kids-learning-home.html` 做了一轮以「可交付」为目标的核验，用本地 WCAG 脚本逐对核验真实像素值，修正如下（均已在实现中生效）：

1. **聚焦环改色（原为硬性失败）**：原 `:focus-visible` 用 `--accent` 描边，在 `--bg` 上仅 **1.92:1**，远低于 3:1。改为 `--fg`：`--bg` 15.11:1、`--surface` 15.78:1、暖橙 hero 上 7.86:1，全场景达标。
2. **用户气泡对比（原为硬性失败）**：`.bubble.u` 原为「暖橙底 + 米白字」仅 **2.01:1**；改为 `--on-hero` 深棕字 **7.11:1**，同时与 hero 用色一致。
3. **学科色「文字必须用墨色」落实到位**：华容道方块数字由 `--games` 改为 `--games-ink`（3.21 → 4.99:1）；拼好态由 `--english` 改为 `--english-ink`（2.51 → 4.90:1）。
4. **`--subtle` 微调**：`#7A7268` 在 `--bg` 上 4.46:1，差 0.04 未过；下调到 `#746E64`（bg 4.76 / surface 4.97），仍明显浅于 `--muted`，去强调层级不变。
5. **隐藏面板的焦点与语义**：`.chatview` / `.sheet` / `.pmodal` 关闭时加 `inert`，打开时解除并把焦点移入面板（返回键 / 关闭键 / 关闭键），关闭后焦点回落到触发元素；`.screen` 在面板打开期间 `inert`。此前关闭的浮层仍可被 Tab 触达、并与 `aria-hidden` 冲突。聊天视图补 `role="dialog"`；标题由 `<b>` 改 `<h2>`。
6. **文案不再被截断**：hero 副文案原带 `nowrap + ellipsis`，中文会被中途省略；改为允许换行（`line-height 1.5`），信息完整。
7. **键盘可用性**：华容道每次移动后把焦点保留在刚移动的方块上（此前整块 `innerHTML` 重绘会把焦点丢到 body，键盘无法连续操作）。
8. **运行时健壮性**：`localStorage` 访问加 `try/catch` 兜底到内存实现——嵌入式预览里存储被拦时不再中断整个脚本；移动端满屏用 `100dvh` 兜底。

**空/加载/错误状态结论**：错误态已具备（答题答错、家长门答错、TTS 不可用 toast、语音异常 toast）；成功态具备（答对、拼好、验证通过）；**空态与加载态本轮不适用**——原型数据为静态演示、无异步请求，不去编造不可达的空/加载界面（违反 §10）。
**触控目标**：全部可点元素 ≥44px（`.qopt` 46、`.pm-done` 48、`.back/.sheet-close/.send` 44、`.play` 56、`.hero-more` 44、`.parent` 46）。
**未达项**：`.avatar` 的 `--on-gold` 在 `--avatar-1` 上 4.36:1——头像为 19px 粗体（≥14pt bold，属大字号，阈值 3:1）且 `aria-hidden`，故通过；如未来把头像可见文字化，需改深色字。
