# 小星老师 · 儿童小游戏设计系统（brand spec）

> 本文件既是「影子配对」卡片的设计依据，也是 chatcube 内儿童小游戏模块的通用规格。
> 来源：chatcube 主题系统（`entry/src/main/ets/models/ThemeColors.ets`）、《儿童模式设计 Spec》
> （`docs/superpowers/specs/2026-09-10-kids-mode-design.md`）、小星老师专属色 `#FF9F43`
> （`models/AssistantModels.ets:189`）。

## 0. 什么是「好看」——审美目标与约束

**受众**：7–8 岁儿童（可独立阅读短句，小手精细动作仍在发育）＋ 旁观的家长。
**场景**：平板横屏，聊天流内嵌的互动卡片，单局 1–2 分钟，无需联网。
**目标**：孩子 3 秒看懂玩法、愿意动手；失败不挫败、成功被明确奖励；家长一眼看到「在练观察力」，
而不是「又在打游戏」。

**品牌气质**：温暖、耐心、有秩序。像一位会蹲下来跟孩子说话的老师的桌面，而不是霓虹游戏机。

**风格参考**：Duolingo 的即时正反馈与圆形大触控目标；暖色纸感记账界面的低彩度底盘；
木质拼图板的实体感（大圆角、厚实块面、柔和投影）。不是玻璃拟态，也不是霓虹渐变。

**信息密度**：低。一屏一件事——一句引导 → 一个游戏区 → 一条进度 → 一个主操作。
与「玩这一局」无关的控件一律移出主视区，不做面向开发者/演示者的控制面板。

**不能出现（反模式）**：紫色或多彩渐变、emoji 充当功能图标、左侧彩条＋圆角卡的通用范式、
hover 把文字调浅、纯线框空壳、编造的数据、每屏多个同级实心主按钮、多个功能相同的入口按钮。
所有颜色只能来自本文件令牌；`:root` 之外不得出现裸颜色字面量。

## 1. 六个 OKLch 令牌（唯一色彩来源）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `oklch(97.9% 0.007 88.6)` | 页面/聊天背景（暖纸 `#FAF8F3`） |
| `--surface` | `oklch(99.4% 0.007 88.6)` | 卡片、气泡（`#FFFDF8`） |
| `--fg` | `oklch(24.9% 0.010 80.6)` | 主文字（`#24211C`，非纯黑） |
| `--muted` | `oklch(52.6% 0.017 84.6)` | 次级文字、说明（`#6F6A60`） |
| `--border` | `oklch(88.4% 0.018 84.6)` | 发丝分隔线（`#DED8CC`） |
| `--accent` | `oklch(78.5% 0.154 60.7)` | 小星老师橙 `#FF9F43` |

**派生令牌**（仅由上述令牌 `color-mix` 得到）：`--accent-soft` 18% 橙／`--accent-ink`
46% 橙＋深墨／`--on-accent` 深墨／`--panel` 比页面更暖的浅底／`--fg-soft` 6% 墨。
**状态令牌**：`--success oklch(72.3% 0.192 149.6)`、`--error oklch(71.2% 0.181 22.8)`，
各自派生 `-ink`（文字）与 `-soft`（底色）。状态色是语义，不是点缀。
**内容色板**（只用于游戏对象插画）：琥珀／青／苔绿／陶土／紫／金黄，加统一的 `--obj-deep` 深色描边。

### 1.1 橙色预算（分层，非「最多两处」）

- **实心 `--accent`**：每屏至多 1 处，只给当前主操作（如发送）。
- **`--accent-soft` 浅橙底**：仅限两类——小星老师身份标识（头像、头像胶囊、模块图标）
  与当前选中态。
- **橙色不得用于正文**；需要橙色文字时用 `--accent-ink`，且只用于短标签。

## 2. 字体

- Display（标题、数字）：`'SF Pro Rounded', 'Hiragino Maru Gothic ProN', 'PingFang SC', -apple-system, 'Noto Sans SC', sans-serif` — 圆润无衬线，儿童友好。
- Body：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Noto Sans SC', system-ui, sans-serif`。
- Mono（计数、元信息、进度）：`ui-monospace, 'SF Mono', Menlo, monospace`。

Display 与 Body 必须成对使用；数字、进度、失误次数一律走 Mono，形成「游戏数据」的质感线索。

## 3. 动效语言

| 令牌 | 值 | 用途 |
|---|---|---|
| `--motion-fast` | `140ms` | 悬停位移、边框/底色反馈 |
| `--motion-base` | `220ms` | 选中、进度点变化 |
| `--motion-shake` | `400ms` | 配对错误的抖动 |
| `--motion-celebrate` | `900ms` | 通关彩纸，每局仅触发一次 |

- 统一缓动 `cubic-bezier(.2, .8, .3, 1)`（起步快、收尾稳）。
- 反馈必须即时：点击到状态变化 < 100ms 可感知。
- 位移克制：悬停最多 `translateY(-3px)`，按下 `scale(.97)`，不做弹跳、不做旋转乱飞。
- `prefers-reduced-motion: reduce` 时，所有动画/过渡降到 `1ms`；彩纸不呈现但仍保留星星文字反馈。

## 4. 交互状态契约

每个可交互元素都要成对定义前景/背景，状态切换后对比度不得低于默认态（禁用态除外）。

| 组件 | 状态 | 表现 |
|---|---|---|
| 图片/影子棋 | 默认 | `--surface` 底、`--border` 描边 |
| | 悬停 | 上移 3px，描边加深（前景色不变，对比不降） |
| | 选中 | `--accent-soft` 底、`--accent` 描边＋柔和投影 |
| | 已配对 | 该对象色相 15% 底、实线描边、右上角 ✓、`aria-disabled`、光标默认 |
| | 错误 | `--error` 描边＋14% 红底＋抖动 |
| 主按钮（发送） | 默认 | `--accent` 底、`--on-accent` 字 |
| | 悬停 | 橙加深约 14%（L 降 0.06–0.12），前景不变 |
| | 按下 | `scale(.96)` |
| 次按钮（描边） | 悬停 | 描边转 `--fg`，加 `--fg-soft` 底 |
| 文字按钮（不玩了） | 默认/悬停 | 由 `--muted` → `--fg`（对比只升不降）＋ `--fg-soft` 底 |
| 输入框 | 聚焦 | `--accent` 描边＋`--accent-soft` 外环 |
| 所有可聚焦元素 | `:focus-visible` | 3px `--accent` 外环，offset 2–3px |

**禁止**：悬停把文字改成 `--muted` 或任何更接近底色的颜色；浅底浅字、深底深字；
唯一例外是禁用态可降低对比。

## 5. 尺寸与可访问性

- 触控目标 **≥48px**（儿童手部精细动作未成熟，宁可大不可小）；本轮移动端最小棋子已提到 48px。
- 圆角：卡片 ≥16px（实际 18px），棋子按比例 14–20px，面板 12px。
- 平板横屏为主要基准；移动端为**重排**而非压缩：5×48px 棋子＋4px 间距可在 320px 内容宽内排下，
  不出现横向滚动。
- 进度点、失误数走 Mono 且带 `role`/`aria-label`；结果与提示用 `aria-live="polite"` 播报。
- 卡片、棋盘、结果都不得出现文字被裁切、溢出或元素遮挡。

## 6. 组件解剖：内嵌游戏卡片

```
appbar（小星老师身份 + 累计星星）
  聊天气泡（引导语）
  card
    card-head   模块图标 + 标题 + 关卡/能力标签 + 状态胶囊
    prompt      一行「怎么玩」
    board       对象行 → 连线层 → 影子行（--panel 底盘）
    progress    进度点 + 失误计数
    actions     本地最佳 + 放弃
    result      结果横幅（成功绿/放弃橙）+ 星星奖励 + 再玩一次
  composer（输入 + 发送）
```

- 状态胶囊：进行中隐藏 → 完成「已完成」成功绿、放弃「已放弃」浅橙。
- 结果横幅内星星徽标在放弃路径必须隐藏，不得显示 `+N 星星`。
- 局部状态覆盖：默认（未选）／进行中／错误／完成／放弃，均有明确视觉与播报。

### 6.1 可复用模板 `game-card-template.html`

本 spec 已落成一个可直接复制、跑通的种子文件 `game-card-template.html`。它把上图的
外壳与卡片固定为 **SHELL**（令牌、状态机、进度、结果横幅、彩纸、最佳记录、对话、无障碍），
只留两处替换点给新游戏：

- **CONFIG**：`title / capability / level / pairCount / bestKey / promptHTML /` 两侧行标题 “彩色图片”与“影子” /
  引导语 / 各状态文案 / `headIcon` / `resultMessage(stars)`。
- **GAME MODULE**：题目数据与渲染判定。必须实现下列适配契约。

| 成员 | 签名 | 作用 |
|---|---|---|
| `pool` | `[{ id, name }, …]` | 题目池，`id` 需唯一且能被 CSS 变量 `--hue-<id>` 着色 |
| `pick` | `(pool, n) → item[]` | 抽本局试题；顺序即来源行顺序（目标行由 SHELL 自动打乱） |
| `isMatch` | `(source, target) → bool` | 配对判定（不要求 `id` 相等，可换成“动物↔食物”等） |
| `glyph` | `(item, mode) → string` | 棋子内联 SVG；`mode` 为 `"source"`（彩色）或 `"target"`（剪影） |
| `label` | `(item, mode, idx) → string` | 棋子 `aria-label`；目标行用位置而非名称，避免剧透 |
| `linkColor` | `(item) → css 颜色` | 连线描边色 |
| `confettiColors` | `string[]` | 通关彩纸用色（可选，缺省用 `--accent`） |
| `labelMatched` | `(source, target, isSource) → string` | 已配对后的 `aria-label`（可选覆盖） |

新游戏只需新增对应的 `--hue-*` 内容色令牌，**不得在 `:root` 之外写裸颜色**；任何超出
“配对／连线”机制的玩法，复用 SHELL 与卡片外壳，另写一个 board 驱动器即可。
内置适配器即「影子配对」，可对照 `shadow-match-card.html` 验证。

## 7. 图像策略

小游戏在本项目中**一律以矢量图形绘制**（参考 `.claude/plans/whack-mole-game.md`：
「视觉（纯 ArkUI 绘制，无外部图片）」）。影子配对的谜题对象为通用图形（鸭子、鱼、树、房子、风筝、钥匙），
不指向任何具体真实事物，因此以自绘 SVG 剪影呈现——这正是该玩法的原生实现介质，而非对真实参照物的替代。
若未来引入真实参照物（真实品牌、人物、地标），必须改用其真实授权图片，不得以剪影代替。

## 8. Do / Don't

**Do**：暖纸底盘、单一橙点缀、大圆角大触控、深墨文字、状态色成对、即时反馈、一屏一件事。
**Don't**：渐变洗底、emoji 图标、彩条卡片、hover 降对比、编造数据、纯线框空壳、
`:root` 外裸颜色、多主按钮、`scrollIntoView`（会破坏内嵌预览）。

## 9. 交付验收清单

- [ ] 颜色全部来自令牌，`:root` 外无裸 hex/oklch。
- [ ] 橙色实心 ≤1/屏，实心主操作唯一。
- [ ] 所有触控目标 ≥48px；320–1920px 无横向滚动。
- [ ] 悬停/聚焦/选中/错误/禁用状态均已定义且对比不降。
- [ ] 空（未选）、进行、错误、完成、放弃五种状态齐全，`aria-live` 播报正确。
- [ ] 无文字裁切、无元素遮挡、无 `{{占位}}`。
- [ ] JavaScript 语法通过；无远程图片依赖。
